# Архитектура MVP

## Поток данных

`GeoJSON / пользовательский контур / синтетические демо-зоны` → `ввод условий и ручных проверок` → `жёсткие ограничения и балл пригодности` → `вместимость контура и предварительные точки` → `сценарий посадки и смета` → `синтетический ML-прогноз` → `календарь и экоэффект` → `индекс приоритета` → `бюджетная очередь` → `GeoJSON / HTML-отчёт`.

Приложение — статический клиент без сервера и аккаунтов. `app.js` отвечает за MapLibre, OpenFreeMap, WMS WorldCover, Open-Meteo, состояния участков и импорт/экспорт. `evidence-review.js` сравнивает исторический класс покрова с отдельной ручной отметкой текущей поверхности. `mvp.js` содержит открытые правила и UI по ТЗ. `planting-layout.js` раскладывает предварительные точки регулярной сеткой внутри полигона с отступом от границ; точки доступны отдельным слоем и файлом GeoJSON. `mvp-model.js` воспроизводимо обучает логистическую регрессию при загрузке страницы. Все сценарии и веса хранятся в `localStorage` браузера; автоматической синхронизации нет. Миграция состояния добавляет 3 демо-полигона без удаления ранее созданных участков.

## Сущности

| Сущность | Поля |
| --- | --- |
| `Site` | `id`, `name`, `geometry` (`Point`/`Polygon`, WGS84), `demo`, `checks`, `observation`, `scenario`, `mvp` |
| `observation` | ручной класс текущей поверхности, источник (`map`/`field`), дата ввода; приложение не проверяет достоверность |
| `mvp` | `purpose`, `soil`, `light`, `road`, `clearance` в метрах, `greenShare` 0–1 или `null`, `source` |
| `scenario` | основной и второй вид, количество, полив, цены, срок ухода, лимит зоны |
| `checks` | ручной осмотр почвы, вода, сети, право; подтверждённый конфликт исключает сценарий |
| `Plan` | общий бюджет, веса четырёх факторов, выбранные зоны, исключения, итоговая смета |

## Логика

- Проблемы выводятся из введённой доли зелени, почвы, дороги и обзорного класса WorldCover. При отсутствии фактора вывода о нём нет.
- Расхождение ручной отметки по карте с WorldCover 2021 исключает зону из бюджетной очереди до осмотра. Отметка полевого осмотра сохраняет расхождение как предупреждение; ручная отметка о воде или сплошном покрытии блокирует посадку. Оба источника и результат сравнения включаются в отчёт.
- Пригодность: сначала ограничения по ширине, засолению и ручным блокировкам, затем объяснимый балл 0–100 по совместимости введённых условий. Каталог видов демонстрационный.
- Вместимость: расстояние между предварительными точками равно условной ширине кроны более крупного выбранного вида, отступ от границы — половине этого расстояния. Если указанное число деревьев не помещается, вид/сценарий исключается из бюджетной очереди. Это только геометрическая схема без полевой проверки.
- Прогноз: логистическая регрессия на 336 синтетических метках с 84 синтетическими проверочными строками. Горизонты 1/2/3 года, риск-факторы и пример изменения полива. Требуется проверка на реальных исходах.
- Смета: саженцы + подготовка + доставка + посадка + уход на 1–3 года + резерв замены, с редактируемыми ценами.
- Приоритет: взвешенные дефицит зелени, социальное назначение, нагрузка и крона на единицу затрат. При пропусках используются нейтральные значения и предупреждение.
- Очередь: только полигоны без известных блокировок и в лимите зоны; до 18 зон перебираются наборы полных сценариев, далее используется жадный отбор. Цель — индекс × ожидаемая крона к 10-му году в пределах бюджета.
- Экологический эффект: иллюстративная крона и условные CO₂/осадки на 5/10/20 лет. Без местной калибровки не годится как фактическая оценка воздействия.

## Расширение после хакатона

Для эксплуатации потребуется сервер с версионированными наборами зон, геоданных и цен; загрузка данных организатора; полевые исходы посадок; специалисты, роли, журнал изменений и HTTPS. Отдельный сервис модели нужен после обучения на реальных наблюдениях. REST API и RAG-ассистент в ТЗ описаны как дальнейшее развитие, в этом локальном MVP их нет.
